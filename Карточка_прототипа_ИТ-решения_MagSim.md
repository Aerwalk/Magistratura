## 2. Функциональная составляющая прототипа ИТ-решения

| Поле | Значение |
|------|----------|
| **Автоматизируемая область** | Складская логистика / Управление запасами |
| **Реализуемая функциональность** | 1) **3D-визуализация склада**: интерактивное отображение склада 16x12 с полками, роботами, БВС, зонами входа/выхода<br>2) **Управление БВС (UAV)**: автоматическое распознавание немаркированных поставок, навигация к зоне приёмки, возврат на базу<br>3) **Управление РТС (роботами)**: 5 специализированных роботов (metal, plastic, electronics, wood, glass) для перемещения товаров<br>4) **Алгоритм маршрутизации A***: поиск кратчайшего пути с обходом препятствий<br>5) **Система задач**: размещение (putaway), изъятие (retrieve), ребалансировка (rebalance)<br>6) **Ребалансировка склада**: автоматическая оптимизация расположения товаров ближе к выходу<br>7) **Аналитика и отчётность**: статистика по товарам, экспорт в Excel с диаграммами<br>8) **Контроль состояния**: отслеживание застрявших роботов, анимации погрузки/разгрузки |
| **Объём реализации (количество пользовательских сценариев)** | 1) **Поставка с меткой** – пользователь добавляет маркированный товар, робот автоматически размещает его на оптимальной полке<br>2) **Поставка без метки** – БВС сканирует товар, распознаёт тип и передаёт задачу роботу<br>3) **Запрос товара** – пользователь запрашивает товар, робот извлекает и доставляет к выходу<br>4) **Ребалансировка** – автоматическое перемещение товаров ближе к выходу на основе спроса<br>5) **Демо-заполнение** – автоматическое заполнение склада демо-данными<br>6) **Экспорт отчётности** – выгрузка статистики в Excel с визуализацией |
| **Проверяемые гипотезы** | 1) Мультиагентная архитектура обеспечивает эффективное распределение задач между БВС и РТС<br>2) Алгоритм A* с динамическим обходом препятствий гарантирует безопасную навигацию роботов<br>3) Ребалансировка на основе метрик спроса оптимизирует среднее время изъятия товаров<br>4) 3D-визуализация позволяет оперативно контролировать состояние склада<br>5) Экспорт данных в Excel обеспечивает возможность дальнейшего анализа эффективности |
| **Метрики автоматизации бизнес-процессов** | 1) Время размещения товара на полку<br>2) Время изъятия товара<br>3) Пройденное расстояние роботами<br>4) Коэффициент использования ёмкости полок<br>5) Количество выполненных операций |
| **Риски, сопряжённые с реализацией прототипа ИТ-решения** | 1) **Ограниченность масштаба**: симуляция ограничена одним складом, не учитывает межскладскую логистику<br>2) **Упрощённая физика**: отсутствие учёта коллизий роботов, времени зарядки, отказов оборудования<br>3) **Статичность среды**: фиксированная планировка склада без возможности реконфигурации<br>4) **Ограниченное распознавание**: БВС использует случайный выбор товара вместо реального распознавания образов<br>5) **Отсутствие интеграции с ERP**: нет связи с реальными системами управления запасами<br>6) **Риск тупиков**: при определённых сценариях возможна блокировка роботами друг друга |
| **Комментарий** | Прототип разработан как демонстрационная система для изучения мультиагентных систем в складской логистике |

## 3. Техническая составляющая прототипа ИТ-решения

| Поле | Значение |
|------|----------|
| **Компоненты ИТ-решения** | 1) Ядро симуляции (simulation core)<br>2) Модуль управления состоянием склада (state management)<br>3) Модуль навигации и маршрутизации (pathfinding A*)<br>4) Контроллер БВС (uav_controller)<br>5) Контроллер РТС (robot_controller)<br>6) Менеджер задач (task_manager)<br>7) Модуль ребалансировки (rebalancer)<br>8) 3D-визуализатор (PyQt5 + pyqtgraph)<br>9) Модуль экспорта (openpyxl) |
| **Способ взаимодействия конечного пользователя с решением** | 1) Графический интерфейс (PyQt5)<br>2) 3D-визуализация склада в реальном времени<br>3) Панель управления (кнопки, комбобоксы, спинбоксы)<br>4) Карта полок с интерактивным кликом<br>5) Лог событий в реальном времени<br>6) Экспорт данных в Excel |
| **Используемые ИТ-решения / ИТ-продукты / Технологический стек** | Python 3.12+, PyQt5 (GUI), pyqtgraph (3D-визуализация), numpy (математика), openpyxl (экспорт Excel), heapq (алгоритм A*) |
| **Характер используемых данных** | Тестовые (демо-данные) |
| **Необходимость интеграции** | Нет |
| **Объём инфраструктурных мощностей, необходимых для реализации прототипа ИТ-решения** | **Тип сервера:** не требуется (desktop-приложение)<br>**Требования к клиентскому ПО:**<br>- ОС: Windows 10/11, Linux, macOS<br>- Python 3.12+<br>- 4 ГБ ОЗУ<br>- OpenGL 3.0+ для 3D-визуализации |
| **Требуемое инфраструктурное ПО** | Не требуется |
| **Необходимость выделения мощностей из общего ИТ-ландшафта** | Нет |
| **Комментарий** | Прототип является автономным desktop-приложением, не требующим серверной инфраструктуры |

## Приложение: Технические характеристики симуляции

| Параметр | Значение |
|----------|----------|
| Размер склада | 16 x 12 ячеек |
| Количество типов товаров | 5 (metal, plastic, electronics, wood, glass) |
| Количество БВС | 1 |
| Количество РТС | 5 (по одному на тип товара) |
| Ёмкость полки | 5 единиц |
| Скорость робота | 0.25 ячейки/тик |
| Интервал симуляции | 50 мс |
| Ёмкость лога событий | 500 записей |
| Максимальное время застревания | 100 тиков |

### Архитектура модулей

```
src/
├── config/          # Конфигурация (товары, цвета, размеры)
├── core/
│   ├── grid.py      # Управление сеткой и полками
│   ├── state.py     # Состояние склада (Singleton)
│   └── pathfinding.py # Алгоритм A*
├── entities/
│   ├── uav.py       # БВС (летающий сканер)
│   ├── robot.py     # РТС (наземный робот)
│   └── base.py      # Базовые функции движения
├── simulation/
│   ├── task_manager.py     # Управление задачами
│   ├── uav_controller.py  # Контроллер БВС
│   ├── robot_controller.py # Контроллер РТС
│   └── rebalancer.py      # Ребалансировка склада
└── ui/
    └── warehouse_app.py   # PyQt5 GUI + 3D визуализация
```
