Карточка прототипа ИТ-решения

1.	Общие сведения о прототипе ИТ-решения
Наименование ИТ-идеи	Мультиагентная система симуляции интеллектуального склада с БВС и РТС
Наименование прототипа ИТ-решения:	ИнтеллектуальныйСклад
Дата составления:	26.03.2026
Владелец прототипа :	Студент	Должность:	-
Менеджер прототипа :	Разработчик	Должность:	-
Заказчик (Площадка):	Университет/кафедра	Должность:	-
Заказчик (ГО):	-	Должность:	-
Короткое описание прототипа ИТ-решения:	Мультиагентная система симуляции склада, включающая беспилотные летательные аппараты (БВС) для распознавания немаркированных поставок и наземные роботы-транспортировщики (РТС) для перемещения материалов. Система обеспечивает 3D-визуализацию склада, управление задачами размещения и изъятия товаров, автоматическую ребалансировку запасов и аналитику складских операций с экспортом данных в Excel.
Характер ИТ-идеи, проходящей прототипирование:	Инновационная 


2.	Функциональная составляющая прототипа ИТ-решения
Автоматизируемая область:	Складская логистика / Управление запасами
Реализуемая функциональность:	1) 3D-визуализация склада: интерактивное отображение склада 16x12 с полками, роботами, БВС, зонами входа/выхода
2) Управление БВС (UAV): автоматическое распознавание немаркированных поставок, навигация к зоне приёмки, возврат на базу
3) Управление РТС (роботами): 5 специализированных роботов (metal, plastic, electronics, wood, glass) для перемещения товаров
4) Алгоритм маршрутизации A*: поиск кратчайшего пути с обходом препятствий
5) Система задач: размещение (putaway), изъятие (retrieve), ребалансировка (rebalance)
6) Ребалансировка склада: автоматическая оптимизация расположения товаров ближе к выходу
7) Аналитика и отчётность: статистика по товарам, экспорт в Excel с диаграммами
8) Контроль состояния: отслеживание застрявших роботов, анимации погрузки/разгрузки
Объём реализации (количество пользовательских сценариев):

**БЛОК 1: Сценарии поставок**

1) Поставка с меткой (единичная) – пользователь выбирает товар и количество, робот забирает с зоны приёмки и размещает на оптимальной полке
2) Поставка с меткой (многократная) – пользователь добавляет несколько единиц одного товара, задачи队列ируются и выполняются последовательно несколькими роботами
3) Поставка без метки (единичная) – БВС вылетает к зоне приёмки, сканирует товар, распознаёт тип (случайный выбор), передаёт задачу роботу
4) Поставка без метки (многократная) – БВС обрабатывает несколько немаркированных единиц, последовательно распознавая каждую
5) Поставка без метки (очередь) – несколько поставок без метки в очереди, БВС обрабатывает их одну за другой
6) Демо-заполнение склада – автоматическое заполнение склада случайным количеством всех типов товаров (2-4 ед.)
7) Поставка при частично заполненном складе – робот находит частично заполненную полку того же товара и добавляет единицы
8) Поставка при полностью заполненном складе – поиск новой пустой полки для размещения товара

**БЛОК 2: Сценарии запросов товаров**

9) Запрос товара (единичный) – пользователь запрашивает 1 единицу товара, робот извлекает с ближайшей полки и доставляет к выходу
10) Запрос товара (многократный) – пользователь запрашивает несколько единиц одного товара, роботы обрабатывают очередь задач
11) Запрос товара (частичное выполнение) – запрошено больше, чем есть на складе, выполняется в пределах остатка
12) Запрос товара (нулевой остаток) – пользователь запрашивает товар, которого нет на полках, система сообщает о недоступности
13) Запрос товара (низкий остаток) – при запросе количества больше доступного, спинбокс автоматически ограничивает максимум
14) Запрос товара (первый в списке) – при выборе недоступного товара автоматически переключение на доступный
15) Запрос товара (refresh) – обновление списка доступных товаров при изменении остатков

**БЛОК 3: Сценарии ребалансировки**

16) Автоматическая ребалансировка по спросу – система анализирует спрос и перемещает товары ближе к выходу
17) Принудительная ребалансировка – пользователь запускает ребалансировку принудительно (force=True)
18) Проверка ребалансировки – контрольная проверка и оптимизация без полной перестановки
19) Ребалансировка при недостаточном спросе – система отказывает при спросе менее 3 единиц (без force)
20) Ребалансировка оптимально заполненного склада – система определяет, что склада уже оптимален
21) Ребалансировка с частичным перемещением – перемещение только части товаров на ближайшие полки

**БЛОК 4: Сценарии управления роботами**

22) Сброс робота в начальную позицию – пользователь сбрасывает конкретного робота на домашнюю позицию
23) Изменение ёмкости робота – пользователь настраивает грузоподъёмность робота (1-5 единиц)
24) Изменение скорости робота – пользователь регулирует скорость движения робота (0.05-1.0)
25) Проверка застрявшего робота – автоматическое определение и сброс робота, не двигавшегося 100 тиков
26) Возврат робота домой – робот без задач автоматически возвращается на домашнюю позицию
27) Назначение задачи свободному роботу – система автоматически распределяет задачи между свободными роботами
28) Блокировка занятыми роботами – другие роботы объезжают роботов в режиме ожидания

**БЛОК 5: Сценарии навигации БВС**

29) БВС в режиме ожидания – БВС на базовой позиции ожидает поступления немаркированного товара
30) БВС вылет к зоне приёмки – при поступлении задачи БВС автоматически летит к IN-зоне
31) БВС сканирование товара – БВС зависает над товаром и выполняет 30 тиков сканирования
32) БВС возврат на базу – после обработки всех задач БВС возвращается на домашнюю позицию
33) БВС непрерывная работа – при наличии очереди БВС сразу летит к следующей поставке
34) БВС смена позиции – БВС корректирует позицию для наведения на цель

**БЛОК 6: Сценарии визуализации**

35) 3D-обзор склада – пользователь вращает и масштабирует 3D-сцену для полного обзора
36) Отображение полок с товарами – цветовая кодировка товаров на полках (5 типов товаров)
37) Отображение уровня заполнения – визуализация количества товаров на каждой полке (0-5)
38) Отслеживание движения робота – анимация перемещения робота по маршруту
39) Отображение перевозимого груза – визуализация товара над роботом при транспортировке
40) Отслеживание БВС – визуализация полёта БВС с лучом сканирования
41) Обновление сцены в реальном времени – синхронизация 3D-визуализации с симуляцией (50 мс)
42) Интерактивная карта полок – клик по ячейке показывает информацию о содержимом
43) Цветовая легенда карты – зелёный (вход), голубой (зона подбора), жёлтый (выход)

**БЛОК 7: Сценарии статистики и аналитики**

44) Просмотр статистики по товарам – таблица: всего, на полках, ушло по спросу

46) Экспорт индивидуального отчёта – отдельный лист с диаграммой для каждого товара
47) Обновление статистики в реальном времени – счётчики обновляются при каждом тике
48) Подсчёт эффективности – метрики: время размещения, время изъятия, расстояние

**БЛОК 8: Сценарии логирования**

51) Типы событий в логе: поставки, размещение, изъятие, доставка, ребалансировка, ошибки

53) Маршрут в обход другого робота – динамический пересчёт при появлении блокировки

56) Приоритет ближайшей точки доступа – выбор оптимальной точки подъезда к полке

**БЛОК 10: Сценарии резервирования**

71) Демо-заполнение при уже заполненном складе – добавление к существующим запасам
Проверяемые гипотезы:

**Бизнес-гипотезы**

1) Мультиагентная архитектура (БВС + РТС) обеспечивает более эффективное распределение складских задач по сравнению с монолитной системой управления. БВС выполняет функции входного контроля и распознавания, освобождая РТС от навигационных задач в зоне приёмки.

2) Разделение специализации роботов по типам товаров (metal, plastic, electronics, wood, glass) позволяет оптимизировать маршруты и сократить время обработки за счёт исключения межтипных конфликтов при выборе полок.

3) Автоматическая ребалансировка на основе метрик спроса (demand hotness) оптимизирует среднее время изъятия товаров путём перемещения популярных товаров ближе к выходу.

4) Снижение среднего расстояния от полки до выхода на 20-30% приведёт к пропорциональному сокращению времени цикла обработки заказа и увеличению пропускной способности склада.

5) Внедрение автоматизированной системы мониторинга и логирования сократит трудозатраты операторов на ручной учёт движений товаров и поиск ошибок в процессах.

**Технические гипотезы**

6) Алгоритм поиска пути A* с динамическим обходом препятствий (других роботов) гарантирует нахождение бесконфликтного маршрута для 95% запросов в условиях нормальной загрузки склада (до 80% ёмкости).

7) Использование Singleton-паттерна для управления состоянием склада (WarehouseState) обеспечивает потокобезопасность и консистентность данных при одновременной работе нескольких агентов (БВС, РТС).

8) Реализация многофазных задач (putaway → to_shelf → put, retrieve → to_shelf → to_exit → home) обеспечивает корректную обработку прерываний и возобновления операций при появлении блокировок.

9) Применение PyQt5 с pyqtgraph для 3D-визуализации обеспечит стабильную частоту обновления сцены (не менее 20 FPS) при размере склада 16x12 и количестве агентов до 10.

10) Экспорт данных в формате Excel с использованием openpyxl обеспечит формирование структурированных отчётов с интерактивными диаграммами для последующего анализа эффективности складских операций.

11) Механизм резервирования полок (reserved_put_shelves, reserved_pick_shelves) предотвращает конфликты одновременного доступа нескольких роботов к одним и тем же ресурсам в 100% случаев.

12) Система автовосстановления (проверка застревания после 100 тиков) обеспечивает устойчивость симуляции кedge-cases маршрутизации без полной остановки системы.

13) Модульная архитектура (core/simulation/entities/ui) обеспечит возможность масштабирования системы для складов большей размерности (до 100x100) без существенной переработки базовых компонентов.

14) Применение очередей задач (deque) для каждого типа товара обеспечит справедливое распределение нагрузки между специализированными роботами и предотвратит голодание (starvation) задач редких типов.

15) Интерактивная карта полок с кликом позволяет оператору быстро локализовать проблемные зоны (тупики, переполненные/пустые полки) и принять решение о ручной корректировке.

Риски, сопряжённые с реализацией прототипа ИТ-решения:

1) Ограниченность масштаба симуляции: прототип моделирует только один склад фиксированной размерности (16x12), не учитывает межскладские перемещения, транспортную логистику и внешние цепочки поставок. Это ограничивает применимость результатов к реальным распределённым складским системам.

2) Качество и полнота демо-данных: используемые тестовые наборы товаров (metal, plastic, electronics, wood, glass) не отражают реальную номенклатуру склада, которая может включать тысячи SKU с различными габаритами, весом, условиями хранения и сроками годности.

3) Упрощённая физика взаимодействия: отсутствие учёта коллизий между роботами, времени зарядки аккумуляторов, износа механизмов, отказов оборудования и погодных условий (для БВС) делает модель менее реалистичной по сравнению с реальной эксплуатацией.

4) Статичность конфигурации склада: фиксированная планировка (расположение полок, проходов, зон входа/выхода) не позволяет исследовать влияние различных топологий склада на эффективность работы алгоритмов маршрутизации и ребалансировки.

5) Отсутствие интеграции с ERP/WMS системами: симуляция работает изолированно, без связи с реальными системами управления запасами, что исключает возможность тестирования сценариев синхронизации данных и автоматического формирования заказов на поставку.

6) Ограниченное распознавание образов БВС: текущая реализация использует случайный выбор типа товара вместо реального компьютерного зрения или RFID-сканирования, что не позволяет исследовать точность и скорость автоматической идентификации в производственных условиях.

7) Риск взаимных блокировок роботов (deadlock): при определённых сценариях одновременного движения нескольких роботов возможна ситуация, когда роботы блокируют друг друга, ожидая освобождения прохода. Текущий механизм защиты (100 тиков) является реактивным, а не превентивным.

8) Сопротивление пользователей внедрению: сотрудники склада могут воспринимать автоматизированную систему мониторинга как инструмент тотального контроля их действий, что приведёт к саботажу или отказу от использования системы.

9) Недостаточная точность алгоритма A* в динамической среде: при высокой плотности роботов алгоритм может находить маршруты, которые становятся непригодными к моменту прохождения, требуя многократного перепланирования и снижения пропускной способности.

10) Субоптимальность эвристик размещения: текущий алгоритм выбора оптимальной полки (shelf_distance_score / hotness) является жадным и может давать локально-оптимальные, но глобально-неэффективные решения при определённых паттернах спроса.

11) Требования к вычислительным ресурсам 3D-визуализации: при отображении большого количества объектов (роботы, товары, анимации) возможно падение частоты кадров ниже критического порога (менее 15 FPS), что негативно влияет на пользовательский опыт.

12) Сложность масштабирования на реальные объекты: параметры симуляции (скорость 0.25, ёмкость 5, сетка 16x12) масштабируются нелинейно при переходе к реальным складам с десятками тысяч единиц хранения и сотнями роботов.

13) Отсутствие механизма обработки срочных заказов: текущая архитектура не предусматривает приоритизации задач, все запросы обрабатываются в порядке поступления, что не соответствует реальным складским процессам с VIP-клиентами и срочными отгрузками.

14) Риск переобучения под демо-сценарии: при длительной разработке и тестировании на ограниченном наборе сценариев система может быть оптимизирована под эти сценарии и показывать низкую эффективность на новых, не встречавшихся ранее паттернах нагрузки.

15) Недостаточная документированность кода: отсутствие подробной технической документации затруднит передачу проекта другому разработчику и масштабирование системы командой, не знакомой с текущей реализацией.

16) Ограниченная расширяемость GUI: PyQt5-интерфейс требует значительной переработки для добавления новых типов агентов, сенсоров или элементов склада, что увеличивает стоимость последующих итераций разработки.

17) Зависимость от проприетарных библиотек: привязка к PyQt5 и pyqtgraph создаёт риски лицензирования и ограничивает возможности развёртывания на альтернативных платформах (веб, мобильные устройства).

18) Отсутствие формального тестирования: код не покрыт unit-тестами, что затрудняет рефакторинг и создаёт риск регрессии при внесении изменений в существующую функциональность.

Комментарий:	Прототип разработан как демонстрационная система для изучения мультиагентных систем в складской логистике. Для промышленного внедрения требуется доработка по указанным рискам.

3.	Техническая составляющая прототипа ИТ-решения
Компоненты ИТ-решения:

1) Модуль конфигурации (src/config/constants.py): содержит определения всех констант симуляции: список типов товаров (metal, plastic, electronics, wood, glass), цветовые схемы для визуализации, параметры склада (GRID_W=16, GRID_H=12), конфигурацию роботов (5 специализированных РТС), параметры БВС (позиция дома, скорость), ёмкость полок (5 единиц), временные интервалы (TICK_MS=50)

2) Модуль управления состоянием склада (src/core/state.py): реализует паттерн Singleton для хранения глобального состояния системы: shelf_state (текущее содержимое полок), stock_total (общее количество поступившего товара), demand (текущий спрос), delivered_total (количество отгруженного товара), event_log (журнал событий deque maxlen=500), очереди задач robot_task_queues для каждого типа товара, механизмы резервирования полок reserved_put_shelves и reserved_pick_shelves

3) Модуль управления сеткой и топологией (src/core/grid.py): определяет структуру склада, функции проверки типа ячейки is_shelf_cell(), генератор всех полок all_shelves(), расчёт точек доступа к полкам shelf_access_cells(), функции оценки расстояния shelf_distance_score() и manhattan(), построение множества проходимых ячеек AISLE_CELLS с учётом полок, проходов, домашних позиций, зон входа/выхода

4) Модуль поиска пути A* (src/core/pathfinding.py): реализует алгоритм A* для навигации роботов: функция astar(start, goal, blocked) возвращает список координат оптимального маршрута, использует приоритетную очередь heapq, евклидову эвристику Manhattan distance, поддерживает динамическое обновление списка заблокированных ячеек для обхода других роботов

5) Модуль сущности БВС (src/entities/uav.py): описывает состояние беспилотного летательного аппарата: позиция в 3D-пространстве pos (x, y, z), состояние конечного автомата (idle, to_inbound, scanning, to_home), счётчик тиков сканирования scan_ticks, глобальный экземпляр uav для доступа из всех модулей

6) Модуль сущности РТС (src/entities/robot.py): описывает наземного робота-транспортировщика: идентификатор id и специализация product, домашняя позиция home, текущая позиция pos и отрисовочная позиция draw_pos, маршрут route и текущая цель current_target, текущая задача task и фаза выполнения phase, перевозимый груз carry, анимационные параметры (delivery_anim_ticks, pickup_anim_ticks, carry_bob), параметры движения speed, механизм определения застревания stuck_ticks, список глобальных роботов robots[5]

7) Контроллер БВС (src/simulation/uav_controller.py): управляет жизненным циклом беспилотника: функция update_uav() реализует конечный автомат состояний, обработка очереди немаркированных поставок uav_scan_queue, навигация к зоне приёмки INBOUND_CELL и обратно на базу UAV_HOME_POS, функция _move_uav_towards() для плавного перемещения, случайное распознавание типа товара из PRODUCTS при сканировании, генерация задач putaway для роботов

8) Контроллер РТС (src/simulation/robot_controller.py): управляет движением и задачами роботов: функция move_robots_one_step() обновляет позицию всех роботов, advance_robot_phases() обрабатывает переходы между фазами задач, обработчики фаз _handle_putaway_phase(), _handle_retrieve_phase(), _handle_rebalance_phase(), функция check_stuck_robots() определяет и сбрасывает застрявших роботов, анимации погрузки/разгрузки с временными параметрами

9) Менеджер задач (src/simulation/task_manager.py): управляет формированием и распределением задач: функции supply_labeled() и supply_unlabeled() для добавления поставок, request_product() для запросов на изъятие, assign_tasks() для назначения задач свободным роботам, алгоритмы выбора оптимальной полки _choose_best_put_shelf() и _choose_best_pick_shelf() с учётом расстояния и спроса, резервирование полок для предотвращения конфликтов

10) Модуль ребалансировки (src/simulation/rebalancer.py): оптимизирует расположение товаров: функция rebalance_warehouse() анализирует текущее состояние и формирует план перемещений, расчёт shelves_by_distance от дальних к ближним относительно EXIT_CELL, формирование очереди задач типа rebalance для роботов, функция check_rebalance_complete() отслеживает завершение процесса, защита от избыточной ребалансировки при низком спросе

11) Модуль логирования событий (src/simulation/state_accessors.py): обеспечивает журналирование: функция log() добавляет сообщения в event_log deque, preload() инициализирует систему, все модули используют единый интерфейс для логирования операций и ошибок

12) Графический интерфейс приложения (src/ui/warehouse_app.py): основной GUI на PyQt5: класс Warehouse3D (GLViewWidget) для 3D-визуализации с использованием pyqtgraph, ScatterPlotItem для отображения полок, роботов, грузов и БВС, GLGridItem для сетки склада, GLLinePlotItem для луча сканирования, класс WarehouseApp (QMainWindow) с панелями управления, статистики, карты и лога, таймер simulation loop с интервалом TICK_MS

13) Модуль экспорта данных (src/ui/warehouse_app.py, метод _on_export_excel): формирование отчётов Excel: библиотека openpyxl, сводный лист с таблицей товаров и диаграммой BarChart, индивидуальные листы для каждого товара, сохранение в формате .xlsx через диалог выбора файла

14) Точка входа приложения (main.py): инициализация PyQt5 приложения, вызов preload() для настройки состояния, демо-заполнение склада demo_fill(), создание и отображение главного окна WarehouseApp(), корректное завершение sys.exit(app.exec_())
